# Character archive schema (`IKC1` v1) — Task 54 batch A (D-T54-1)

Generated by `rust/tools/extract/extract-character.mjs`. Outputs in this
directory: `char.bin.gz` + `char.json` (manifest) + `char-poses.json` (pose
tables). Deterministic: re-running against the same upstream commit yields
byte-identical files (TR-3.4 discipline). All integers little-endian; all
floats IEEE-754 f32 unless noted.

Quantization口径 ≡ `extract-props.mjs` (`IKP1`): pos i32 millimetres, normal
i16 ×1000, vertex colour u8 (linear), welded on the 1e-3 quantisation grid and
content-hash (sha256 over quantised verts + index list) deduplicated into a
template table.

## Binary layout (`char.bin.gz` = zlib gzip, level 9)

```
u32  magic            0x31434B49 ('IKC1' read as LE bytes)
u32  version          1
u32  templateCount
u32  instanceCount
templateCount × {
  u32 vertexCount; u32 indexCount; u32 triCount   (triCount = indexCount/3)
  vertexCount × {
    i32 x, i32 y, i32 z          millimetres, part-local (bone-local) space
    i16 nx, i16 ny, i16 nz       ×1000, unit length
    u8  r, g, b                  vertex colour (Builder `col`, linear)
  }
  indexCount × u32               triangle list
}
instanceCount × {
  u32 templateId
  u16 boneId                     index into manifest `rig.boneNames` ∪ pseudo bones
  u32 partId                     index into manifest `parts[].id` (sorted part keys)
  f32 m[12]                      bone-local 3×4 row-major
                                 [r0 r1 r2 t0 / r3 r4 r5 t1 / r6 r7 r8 t2]
}
```

Instances are NOT sorted by template; the manifest `parts[]` table carries the
same `id`/`template`/`matrix`/`bone` for cross-check. `meta.binSha256` is the
sha256 of the **gzipped** bytes.

## Mount bones

`boneId` indexes the 87 real bones (`BONE_NAMES`, character-geo.js) plus two
pseudo mounts appended in the manifest (`rig.pseudoBones`):

- `@kid` — the kid Group (skinned parts: skin / cloth / hair / eyes). Their
  geometry is authored in kid space and emitted at rest pose with the identity
  matrix; skinning is batch C's concern (rigid-mount approximation allowed).
- `@model` — the model Group (squid parts; rigid, not skinned).

Real-bone mounts are computed as `inverse(bone.matrixWorld) × mesh.matrixWorld`
on the real scene graph after `updateMatrixWorld(true)`, i.e. the exact rest
transform a mesh sits at under its bone (tank glass/fill under `tank`, bomb
under `handL`, weapons under `handR`/`handL` through the pivot→off chain).

## Part keys (`parts[].key`)

- `<part>:<tier>` — kid parts, tier ∈ `hero|game|far`, dumped through the real
  `_tierParts()` path (far decimation ≡ `_tierProps`): `skin`, `cloth`, `eyes`,
  `tankGlass`, `tankFill`, `squidBody`, `squidDark`, `squidEyes`,
  `hair0..hair7` (all 8 `HAIR_STYLE_NAMES`).
- `bomb:body|ink` — idle sub prop (`getSubDef('bomb')`); `extra` carries the
  `inHandL` frame + grip spec.
- `weapon:<kind>:<slot>[@L]` — per weapon kind over `WEAPON_KINDS` (11) +
  `SPECIAL_WEAPON_KINDS` (4). Slot ∈ `body|ink|farBody|farInk|part:<name>|drum|
  drumCaps|spin|glow|farDecim:body|farDecim:ink`. `@L` = second (dual) instance
  under `handL` (dualies full instance; twins mirrored `pivotL`).
  `farDecim:*` = `farGeometry(def.body,700)` / `farGeometry(def.ink,300)` — the
  runtime far-tier swap (`_animWeapon`).

`matClass` per part ∈ `skin|cloth|hair|eye|squid|dark|glass|fill|plastic|ink|
lamp|glow` — the Rust side buckets these into StandardMaterial variants.

## Manifest (`char.json`, stable-json key order)

- `meta` — `source.commit` (git HEAD, the only non-determinism exception),
  `source.files`, bin sizes + `binSha256`, `counts` (templates/verts/tris/
  instances/parts/bones/weaponKinds/tiers/hairStyles), canonical extraction
  `style` (rookie preset `{hair:0,skin:0,outfit:0,eyes:0,hat:0,brows:0}`),
  `quant` description.
- `rig` — `boneNames` / `boneParent` (object) / `boneIndex` / `hairMax` /
  `hairSegs` / `aimPivot` / `fistOffset` / `gripHoleL` / `rest` (kid-space rest
  positions, real `getRestPositions(style)`) / `boneInverses` (87×16 f64, real
  `getBoneInverses(style)`) / `hairRest` (per style 0..7: name, rest bone
  positions, strand meta `{dir,len,K,G}`) / `pseudoBones`.
- `parts[]` — `{key,id,tier,bone,matClass,shadow,template,verts,tris,matrix,extra}`.
- `weapons.<kind>` — static frame hierarchy + instance list:
  `frames` (`pivot` = FIST_OFFSET/GRIP_HOLE_L bone-local pos, `off` pos+quat =
  def.inHand, `inHand`/`inHandL`, `gripR`/`gripL` specs `{pos,handZ,handY}`,
  `handR`/`handL` frames, `muzzle`, `twirl`, `drumAt`, `spinAt`, `drumR`,
  `drawLen`, `dual`, `mirrorDual`, `left` = {pivot,off} for dualies),
  `parts.<name>` = `{pivot,mat,lamp{color,emissive,intensity,roughness}}`,
  `instances` = part keys. Dynamic pump/trig/spin motion is NOT baked — it
  stays in `animateWeapon` (batch B/C ports the formulas).
- `weaponKindList` / `specialRefs` — kind name references only: the five held
  special props (kraken/speaker/missile/jetpack/crab) live in
  `../props/special.bin.gz` and are deliberately NOT re-extracted; other
  `SUB_KINDS` and kit weapons (blade/bowl/brolly/mitts/bow) are batch-C scope.

## Pose tables (`char-poses.json`, stable-json)

Literal-block slices + `new Function` eval from `src/game/character.js` /
`src/game/character-style.js` (markers pinned with `assertContains`; no
hand-typed values):

- `poseChannels` — all 66 channel indices + `PN` (=126), computed from the real
  pose-bank layout; `XCH` = expression channel list `[BROW,BROWY,EYE,MCURVE,
  MWIDTH,MOPEN,MTILT,SQUINT]`.
- `rigConst` — ANKLE_H / HIPW / BALL_Z / HEEL_Z / HEAD_CTR.
- `HOLD` — full per-kind hold-state table (13 kinds incl. blade/mitts/bow kit
  entries), `HOLD_HERO`, `ANIM_OF` family mapping, `NO_TWIRL`, `BOW_CANT`,
  `AIM_PIVOT`.
- `STANCE_IDLE` / `STANCE_LOCK` / `SHUFFLES` / `FIDGETS` / `FIDGET_LEN` /
  `K_GOG_*` / `K_LOOK_*` / `K_TANK_*` / `K_MENU_*` / `K_EM_*` (6 form curves) /
  `K_DV_*` (6 dance curves) / `K_SL_*` (slosh keys) / `FINGER_SPREAD` /
  `DANCE_VARIANTS`.
- `blinkCurve` — function source verbatim + parsed default params (`c/h/o/lag/
  amp/dbl/squeeze`) + the pinned constructor line.
- `expressions` — the 23 `X_*` / `E_*` expression delta tables.
- `style` — `SKIN_TONES` / `SKIN_NAMES` / `OUTFITS` / `OUTFIT_NAMES` / `IRIS` /
  `IRIS_NAMES` / `HAIR_STYLE_NAMES` / `HAIR_STYLES` (sliced blocks, cross-checked
  against the real module exports at extraction time).

## Known deviations (batch A)

1. Skinned kid/hair/eyes parts are emitted rigid at kid space (`@kid`,
   identity); skin weights are dropped. Batch C decides re-rigging.
2. Weapon "sub-frame" poses = the static frame hierarchy (pivot/off/part
   pivots/drum/spin/muzzle/handR/handL); animated pump/trig/spin offsets stay
   in `animateWeapon`.
3. Spring hz·ζ literals stay at their `spr()` call sites in character.js
   (batch B ports them with the formulas).
4. Outfit-coupled parts are not extracted (canonical style = outfit 0 base tee).
